# History

Rules for updating and cleaning up a branch.

## Requirements

### MUST

- A branch MUST be updated from the integration branch by rebase or
  fast-forward.
- A rewritten branch MUST be pushed with `--force-with-lease`.
- A meaningful intermediate commit MUST be preserved.

### MUST NOT

- A branch MUST NOT receive a merge commit from the integration branch.
- A shared branch MUST NOT be rewritten without the agreement of every
  contributor working on it.
- The integration branch MUST NOT be rewritten.

## Recommendations

### SHOULD

- A temporary correction SHOULD be recorded as a
  [fixup commit](#cleaning-up-commits).

## Updating a branch

Rebase the branch onto the latest integration branch:

```bash
git switch <branch>
git pull --rebase <remote> <integration-branch>
```

Rebase a branch created from another branch onto the latest integration branch:

```bash
git fetch <remote>
git rebase --onto <remote>/<integration-branch> <old-base> <branch>
```

Push the rewritten branch:

```bash
git push --force-with-lease <remote> <branch>
```

## Fixup messages

- A temporary fixup commit uses `fixup! <target-subject>`, as generated by
  `git commit --fixup=<commit>`. The fixup message disappears when the correction
  is folded into its target by [autosquash](#cleaning-up-commits).

## Cleaning up commits

Fold a correction into an earlier commit:

```bash
git commit --fixup=<commit>
git rebase -i --autosquash <base>
```

Reword, reorder, or edit earlier commits:

```bash
git rebase -i <base>
```
